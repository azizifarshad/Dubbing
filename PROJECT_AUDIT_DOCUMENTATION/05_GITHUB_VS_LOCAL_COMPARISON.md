## 3. Detailed Analysis of Discrepancies

### Discrepancy 1: The `Dubb/` Nested Clone
- **Finding**: Inside the local project root, a directory named `Dubb/` contains `.gitattributes` and its own internal `.git` repository initialized with commit `d5cce9c` pointing to remote `https://github.com/azizifarshad/Dubb.git`.
- **Explanation**: This was created by an accidental `git clone` command into the wrong active working directory.
- **Risk Assessment**: If a developer accidentally runs `git add .`, this directory could be added as an unlinked Git directory entry or corrupt repository status.
- **Recommendation**: Delete the `Dubb/` folder completely from the workspace.

### Discrepancy 2: Duplicate Pre-Compiled Installers
- **Finding**: Three separate copies of `Dubbing-Vidans-Setup.exe` exist locally:
  1. `Dubbing-Vidans-Setup.exe` (Root): 365,010,931 bytes (Timestamp: 11/9/2026)
  2. `Sadra\1-نصاب اصلی نرم افزار\Dubbing-Vidans-Setup.exe`: 365,010,931 bytes (Timestamp: 11/9/2026)
  3. `dist-installer\Dubbing-Vidans-Setup.exe`: 365,038,648 bytes (Timestamp: 11/11/2026 - v1.0.1)
- **Explanation**: The installer was compiled multiple times into different directories.
- **Risk Assessment**: The installer in the root and `Sadra/` is an older build and occupies ~730 MB of redundant disk space.
- **Recommendation**: Keep only `dist-installer\Dubbing-Vidans-Setup.exe` and update `Sadra/1-نصاب اصلی نرم افزار` to point to the newest build.

### Discrepancy 3: Private Cryptographic Keys Stored in Working Tree
- **Finding**:
  - `tools/license-generator/keys/owner_private_key.pem`
  - `tools/update-signer/keys/update_signer_private_key.pem`
  - `Sadra/2-ابزار صدور لایسنس/keys/owner_private_key.pem`
- **Explanation**: These are genuine asymmetric private signing keys used by the software owner.
- **Risk Assessment**: While they are properly ignored in `.gitignore`, storing live production private keys in a working repository tree carries inherent operational risks:
  - Accidental modification of `.gitignore` could expose them in a future commit.
  - Delivering the `Sadra/` folder to a customer would immediately leak the master private signing key.
- **Recommendation**: Move private signing keys to an external secure directory or password-protected vault outside the project directory.
