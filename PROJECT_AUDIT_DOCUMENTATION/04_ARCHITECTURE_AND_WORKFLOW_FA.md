# بخش ۴: معماری فنی، گردش کار و دیاگرام‌های اجرایی (Dubbing Vidans)

## ۱. نمای کلی معماری سیستم

نرم‌افزار **دوبله ویدانس** بر پایه یک معماری ترکیبی کلاینت-سرور برای سیستم‌عامل ویندوز طراحی شده است. برای دستیابی به سبکی، سرعت فوق‌العاده در باز شدن، و حذف لایه سنگین الکترون (Electron)، این پروژه از **میزبان فرآیند سی‌شارپ (C# Process Launcher)** به عنوان لایه پیوند با سیستم‌عامل استفاده می‌کند.

```
+-----------------------------------------------------------------------------------+
|                           میزبان دسکتاپ ویندوز                                    |
|  +-----------------------------+         +-------------------------------------+  |
|  | DubbingVidans.exe (لانچر)  | ----->  | پنجره اختصاصی مرورگر (Edge / Chrome)|  |
|  | - بررسی و تزریق PATH       |         | - حالت کیوسک: --app=http://...      |  |
|  | - نظارت بر پروسه سرور      |         | - پروفایل و کش ایزوله شده دسکتاپ    |  |
|  +-----------------------------+         +-------------------------------------+  |
|                 |                                          |                      |

|  +-----------------------------+         +-------------------------------------+  |

|  | - پورت محلی 3000            |         | - ۵ مرحله پردازش و تدوین پروژه     |  |
```

## ۲. گردش کار گام به گام در ۵ مرحله استودیو

### مرحله ۱: بارگذاری رسانه و استخراج زیرنویس
1. کاربر فایل تصویری یا صوتی را وارد برنامه می‌کند.
2. سرور از طریق دستورات FFmpeg صدای ویدیوی ورودی را با کیفیت ۱۶ بیتی استریو PCM 44100Hz استخراج نموده و بافر صوتی آن را برای تایم‌لاین ارسال می‌کند.
3. در صورت درخواست رونویسی، اسکریپت `local_whisper.py` به صورت ۱۰۰٪ آفلاین مدل کوانتایز شده CTranslate2 را فراخوانی کرده و زیرنویس انگلیسی را با زمان‌بندی دقیق هر کلمه استخراج می‌کند.

### مرحله ۲: استودیوی ترجمه و رتبه‌بندی کاندیداها
1. خطوط دیالوگ به موتور ترجمه هوشمند ارسال می‌گردد.
2. ۳ کاندیدای ترجمه (وفادار، فشرده، محاوره‌ای) ساخته می‌شود.
3. ماژول `durationPredictor.ts` طول صحبت فارسی را بر اساس هجاها و مکث‌ها تخمین می‌زند.
4. ماژول `candidateScorer.ts` با ترکیب نمره معنایی، روانی و تطابق زمانی بهترین گزینه را انتخاب می‌کند و گاردریل‌های ارزیابی (حفظ اعداد و واژگون نشدن مفهوم منفی) صحت آن را تایید می‌کنند.

### مرحله ۳: استودیوی سنتز صدا
1. صداپیشگان کالیبره شده (`Puck`, `Charon`, `Kore`, ...) به کاراکترها اختصاص می‌یابند.
2. با موتور گوگل یا روش ترکیبی محلی، صوت گفتار فارسی با کیفیت استودیویی تولید می‌شود.
3. تفاوت میان زمان هدف ویدیو و زمان گفتار تولیدشده در جدول پایش منعکس می‌گردد.

### مرحله ۴: تایم‌لاین تعاملی و موتور خودکار رفع تداخل‌ها (AutoFix)
1. شکل‌موج صداها و بلوک‌های دیالوگ روی تایم‌لاین به نمایش درمی‌آیند.
2. موتور ۶ مرحله‌ای AutoFix حواشی سکوت دیجیتال را تحلیل می‌کند.
3. با الگوریتم کشش زمانی **WSOLA** بدون تغییر زیروبمی، زمان صوت متناسب با صحنه تطبیق داده می‌شود.
4. دیالوگ‌ها در فضاهای خالی قبل یا بعد جابه‌جا می‌شوند تا از تداخل گفتار جلوگیری به عمل آید.
5. سیستم اسنپ‌شات امکان بازگشت کامل ۱۰۰٪ تغییرات را با یک کلیک فراهم می‌آورد.

### مرحله ۵: استودیوی خروجی و برندینگ
1. ترک‌های صوتی به صورت استریو ۴۸ کیلوهرتز در یک فایل مستر ادغام می‌شوند.
2. اندپوینت `/api/render-dubbed-video` مجوز لایسنس معتبر سیستم را بررسی می‌کند.
3. اسکریپت `mux_video.py` ویدیوی اینتروی استودیو (`intro.mp4`) را از کش نرمال‌شده الحاق کرده، لوگوی شفاف را در گوشه تصویر قرار داده و فیلم نهایی MP4 را با انکود پایدار تحویل می‌دهد.

## ۳. معماری رمزنگاری لایسنسینگ آفلاین (Ed25519)

سیستم صدور و تایید لایسنس نرم‌افزار به صورت کاملاً غیروابسته به شبکه طراحی شده است:

```
[سیستم مشتری]                                         [مالک نرم‌افزار]
   |                                                        |
   |-- 1. استخراج مشخصات سخت‌افزاری (CPU, UUID, Disk)        |
   |-- 2. ایجاد هش SHA-256 و کلید موقت دستگاه               |
   |-- 3. تولید فایل درخواست فعال‌سازی (.vidansreq) --------->|
   |                                                        |-- 4. باز کردن درخواست در LicenseGenerator.exe
   |                                                        |-- 5. تایید امضای دیجیتال دستگاه مشتری
   |                                                        |-- 6. امضا با کلید خصوصی مالک (owner_private_key.pem)
   |<-- 7. تحویل فایل لایسنس دائمی (.vidanslic) ------------|
   |
   |-- 8. اعتبارسنجی با کلید عمومی سخت‌کد شده
   |-- 9. تطبیق هش سخت‌افزار لایسنس با رایانه فعلی
   |-- 10. ذخیره در C:\ProgramData\DubbingVidans
   v
[فعال‌سازی دائمی و نامحدود استودیو]
```

## ۴. معماری سامانه به‌روزرسانی امن (Auto-Update)

1. **جداسازی کامل کلیدها**: کلید امضای بسته‌های آپدیت (`update_signer_private_key.pem`) کاملاً مستقل از کلید صدور لایسنس است.
2. **بررسی اصالت با الگوریتم Ed25519**: نرم‌افزار فایل `update-manifest.json` را دانلود کرده و امضای دیجیتال آن را با کلید عمومی آپدیت بررسی می‌کند؛ هرگونه دستکاری در محتوای فایل یا سرور منجر به رد فوری بسته خواهد شد.
3. **تایید تمامیت فایل با هش SHA-256**: پیش از اجرای هر فایل نصاب دانلودی، هش ریاضیاتی آن محاسبه شده و با مانیفست مقایسه می‌شود.
4. **حفظ اطلاعات کاربر**: تمام فعال‌سازی‌ها و فایل‌های دیتابیس در `C:\ProgramData\DubbingVidans` در زمان ارتقای نسخه دست‌نخورده باقی می‌مانند.
